# D5 联调执行清单

> 当前状态：代码已经合并到 `main`，后端和前端静态检查均通过。
> 下一步：启动真实服务，跑通 `上传 -> 分析 -> 档案`，可选再测 `/api/qa`。

## 联调方式：每人本地各起一套前后端

本项目不要求共享某个人电脑上的后端。**每个人在自己的电脑上同时启动后端（8000）和
前端（3000），前端通过 `/api/*` 代理自动连到本机后端**，互不依赖别人的机器，也
不会出现「别人打不开」的问题。

> 关键点：前端 `next.config.ts` 里的 `localhost:8000` 指的是「跑前端这台机器自己」，
> 不是某个人的电脑。只要前端和后端在同一台电脑上，默认配置即可直接工作。

### 联调顺序

1. 每人先在本机启动后端并确认 `curl http://localhost:8000/health` 返回 `{"status":"ok"}`。
2. 每人再在本机启动前端并打开 `http://localhost:3000`。
3. 赵越提供一份用于联调的 PDF 或 DOCX 样本（发给需要演示的人即可）。
4. 各自在前端执行一次完整流程。
5. 发现错误时记录请求、状态码和返回内容，交给对应负责人。
6. 联调通过后，由赵越更新工作日志并归档样本信息。

### 需要连别人电脑的后端时（可选，默认不用）

只有在「前端跑在 A 电脑、却要连 B 电脑上的后端」时才需要额外配置。在 `frontend/`
下复制 `.env.local.example` 为 `.env.local`，把后端地址改成 B 电脑的局域网 IP：

```dotenv
NEXT_PUBLIC_API_BASE=http://192.168.x.x:8000
```

并让 B 电脑的后端监听局域网（`uvicorn app.main:app --host 0.0.0.0 --port 8000`）。
日常联调请优先使用「每人本地各起一套」的方式，不要默认依赖别人的 IP。

## 沈一：启动后端

### 检查密钥

确认本地 `.env` 中已经配置：

```dotenv
DEEPSEEK_API_KEY=你的 DeepSeek key
```

`.env` 不能被提交到 GitHub。

### 安装并启动

```bash
python -m pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

### 验证后端

```bash
curl http://localhost:8000/health
```

预期返回：

```json
{"status":"ok"}
```

接口文档地址：

```text
http://localhost:8000/docs
```

### 联调时保持运行

整个联调期间保持后端运行。如报错，保留完整 traceback 和请求参数。

## 赵越：准备样本与记录

### 准备样本

准备至少一份普通 PDF 或 DOCX。推荐使用文字层正常、无需 OCR 的文件，先验证主流程。

如果演示扫描件，再另外准备一份扫描版 PDF，并确认沈一环境已安装 Tesseract 和 Poppler。

### 记录内容

记录以下信息：

- 样本文件名、格式、页数
- 后端是否返回 `upload_id`
- 分析是否返回 `completed`
- 前端是否显示六大模块
- 证据弹窗、标签筛选和人工修正是否可用
- 如有错误，记录状态码和返回体

### 完成后更新

更新 `赵越工作日志.md`，写清本轮联调结果和剩余问题。

## 肖一飞：启动前端

### 安装并启动

```bash
cd frontend
npm ci
npm run dev
```

打开：

```text
http://localhost:3000
```

### 执行联调

1. 在页面上选择样本文件。
2. 等待“分析中”结束。
3. 确认页面显示候选人档案。
4. 检查六大模块：
   - 基本信息
   - 教育与工作
   - 奖项与经费
   - 论文与影响
   - 学术服务
   - 综合评价
5. 点击证据，确认弹窗和来源链接正常。
6. 使用关键词或标签筛选。
7. 修改一条证据状态，确认页面同步变化。
8. 可选：通过接口或后续页面测试 `/api/qa`。

### 如出错

记录：

- 浏览器控制台错误
- 后端日志
- 请求 URL 和响应内容

如果是前端问题，由肖一飞修复；如果是后端问题，转给沈一。

## 联调成功标准

全部满足即可确认 D5 完成：

- `/health` 返回 `200`
- `/api/upload` 返回 `201` 和 `upload_id`
- `/api/analyze` 返回 `200` 和 `status=completed`
- `/api/profile` 能按 `upload_id` 或 `profile_id` 返回档案
- 前端能展示六大模块和证据
- 证据弹窗、筛选和人工修正可交互
- 浏览器没有 CORS 报错
- 可选 `/api/qa` 能返回答案和证据

## 需要特别注意

- 普通 PDF/DOCX 不需要 OCR。
- 扫描件需要 Tesseract 和 Poppler；未安装时 OCR 测试会跳过。
- 后端错误返回可能是嵌套 `detail` 对象，前端已兼容。
- 联调通过前不要修改 `schema.json` 或 `api.md`。
