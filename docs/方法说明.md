# Project 1 方法说明

## 项目目标

本项目把候选人的 CV、Cover Letter、Research Statement 和 Teaching Statement
转换为结构化、可检索、证据可追溯的候选人档案，并支持基于档案回答问题。

核心原则：

- 事实与判断分离。
- 每个事实尽量附带来源和证据。
- 找不到公开证据不等于声明为假。
- 冲突信息必须提示人工复核，不能被系统静默覆盖。

## 输入与输出

输入：

- PDF
- DOCX
- 每次最多 4 份文件
- 单文件上限 10 MB

输出：

- `schema_version`
- `candidate`
- 六大模块结构化档案
- 每条事实对应的证据对象

## 系统流程

```text
文件上传
  -> PDF/DOCX 解析
  -> 扫描件 OCR 回退
  -> DeepSeek 结构化抽取
  -> schema 校验
  -> 公开来源核验
  -> 返回候选人档案
```

## 六大模块

### 基本信息

记录姓名、机构、职位、研究方向、最高学历、技能、优势、待核实项和证据。

### 教育与工作

记录教育经历和工作经历：

- 学校、专业、导师、学位
- 起止日期
- 项目与成果
- 工作机构、职位、职责
- 每条记录对应的证据

### 奖项与经费

记录奖项名称、年份、颁发机构，以及资助项目、资助方、金额、币种、角色和证据。

### 论文与影响

记录论文标题、年份、作者角色、发表载体、类型、排名、引用量、查询日期、
代码仓库、Stars 和证据。

### 学术服务

记录服务类型、组织或会议、角色、年份、研究领域和证据。

### 综合评价

记录整体总结、优势、风险和分维度评价。综合评价是模型基于事实形成的判断，
必须有证据支持。

## 证据对象

每条结论建议携带以下证据字段：

| 字段 | 是否必填 | 含义 |
|---|---|---|
| `source` | 必填 | 来源名称，如文件名、机构官网、文献数据库 |
| `source_url` | 必填 | 可打开的来源链接，没有则填 `null` |
| `evidence` | 必填 | 支持结论的原文摘录或检索摘要 |
| `evidence_status` | 必填 | 证据状态 |
| `query_date` | 必填 | 查询日期 |
| `page` | 可选 | 页码 |
| `source_type` | 可选 | 来源类型 |
| `notes` | 可选 | 备注 |

## 证据状态

### `confirmed`

文档明确写出，且没有矛盾，或者外部权威来源与声明一致。

### `not_found_public`

公开来源暂时没有查到相关信息。

该状态不表示声明为假，只表示当前无法通过公开来源确认。

### `to_verify`

文档写得含糊，或者公开来源只能提供部分线索，需要人工复核。

### `conflict`

多个来源对同一事实给出不一致信息，必须保留双方证据并提示人工判断。

## 外部核验

### 论文

论文类声明使用 Crossref 和 OpenAlex：

1. 检索标题接近的论文。
2. 比较年份，允许 1 年容差。
3. 标题和年份都匹配时标记为 `confirmed`。
4. 标题匹配但年份冲突时标记为 `conflict`。
5. 只有部分相似时标记为 `to_verify`。
6. 查不到时标记为 `not_found_public`。
7. 网络或服务异常时标记为 `to_verify`，不把故障误判为造假。

### 非论文声明

奖项、经费、职位和机构等声明使用网页搜索补充公开线索。

网页搜索不能自动确认真伪，因此通常标记为 `to_verify` 或
`not_found_public`，并保留链接供人工打开核对。

## 缺失与冲突处理

- 未知信息用 `null` 或空数组表示。
- 不推测、不补全文档中没有明确写出的信息。
- 日期支持 `YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`。
- 无法确定日期时使用 `null`。
- `conflict` 必须保留至少一条可追溯证据。
- 人工修正只改变当前浏览器会话中的展示状态，不直接修改后端档案。

## 人工修正

证据详情弹窗允许把证据状态修改为：

- `confirmed`
- `not_found_public`
- `to_verify`
- `conflict`

该功能用于演示人工介入流程，不用于自动改写原始材料。

## 当前限制

- 上传和档案存储为进程内缓存，不适用于生产部署。
- `/api/analyze` 是同步接口，外部核验可能耗时较长。
- 扫描件 OCR 需要 Tesseract 和 Poppler。
- 网页搜索使用免费后端，可能受速率和反爬限制。
- 问答功能依据现有档案回答，不能超出档案编造事实。
- 前端默认使用相对路径代理到本机后端；跨机器联调需额外配置。

## 合同来源

字段、枚举和必填规则以 `docs/schema.json` 为准。

接口路径、请求和响应结构以 `docs/api.md` 为准。
